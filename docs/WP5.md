# WP-5 — moses.dll: `missing` / `unused` exports (branch `wp5`)

Goal: every export of moses.dll has a 1:1 port with its `// moses.dll 0x...` comment (the 4 `missing` and the 56 `unused`
rows of `COMPLETENESS.md`), plus a portable text backend. `COMPLETENESS.md` / `ENGINE_API_COVERAGE.md` are regenerated by
the integrator (`python -I tools/engine_coverage.py`); the address check done by hand: all 60 addresses are present in `moses/*`.

Tests: `tests/Moses5_Test.cpp` (156 checks), run at the end of `--engine-test 1` (so `tools\build-engine.bat test` covers it).
Headless: software surfaces, temporary files in the current folder (removed), fake clock, no audio device, no window.

## Deviations / hazards (all marked in the code)
* `CObjCache`: original leaks the GDI objects (destructor runs with the base vtable) and aliases/double-frees key blocks when the cache is full; the port releases objects and recycles the evicted key block.
* `CResfile::load` multi-chunk offset bug preserved (see `moses.md` sec. 12).
* `CDrawMeta::Init` does not recalc the bounds in the original (invisible until moved); the port does. `display` uses the object rect without `pos` (original quirk, kept).
* `CDibData::Read` keeps the palette (original drops it); `Write` supports more than the original's 8-bit-only path.
* wp9-owned files touched minimally: `moses/Mem.h` (comment only), `moses/DrawView.h` (`SetPalette` forwarder + `Profile` declaration), `platform/Midi.h` (inline `BreakLoops`). No ini function, debug overlay or `RemapDrums` code was touched.

## Remaining / not done
* Live MIDI channel mute / tempo change while a sequence is playing (needs a software sequencer; wp9 owns the MIDI backend).
* EMF: regions, alpha/transparent/gradient blits, EMF+ records, text paths, dashed/hatched/pattern styles, rotated text, winding fill (see `DrawMeta.h`).
* A physical CD drive (MCI cdaudio) and non-WAV track files (ripped `.ogg/.mp3` would need a decoder).
* Aaron: the ported Aaron does not create `CGdiPenCache`/`CGdiBrushCache` (the original keeps them in `Scene +0x690/+0x694`); wp4 owns `aaron/*`. Assigning them is a one-liner per drawable now that the pointers exist.
* `engine_coverage.py` was not re-run (needs `pefile` and the game folders); the address search was verified by script on `COMPLETENESS.md`.
